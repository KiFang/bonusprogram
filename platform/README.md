# ARTCHIEVE SERVICE (АРТНАДА СЕРВИС)

Платформа для художников. Требования: `../docs/platform/TZ-v0.1.md`, решения: `../docs/platform/DECISIONS.md`.
Артоки (бонусная программа) живёт отдельно в корне репозитория и пока не затронут.

## Что уже есть (каркас v0.1)
- Next.js 16 (App Router, TypeScript), PostgreSQL 16, Docker Compose, Caddy (HTTPS).
- Вход по одноразовому коду на почту. Новая почта ведёт на короткую анкету (ник, имя, дата рождения, согласие).
  Младше 14 лет регистрация закрыта, 14–17 лет получают аккаунт без заказов и прайса.
- Полная схема базы из ТЗ и правила, которые проверяет сама база (подростки, доли этапов, неизменность условий заявки,
  отсутствие 18+ в файлах). Тесты: `npm run db:test`.
- Дизайн-система: две темы (светлая и тёмная), «скетчевые» рамки и тени, адаптивная вёрстка.
- Лимиты запросов, защита кодов (5 попыток, 10 минут, хэш в базе), сессии (в cookie токен, в базе его хэш),
  заголовки безопасности, `robots.txt`, `/healthz`.
- Служебная страница образцов шрифтов `/dev/fonts` (в продакшене закрыта).

Не сделано (следующие шаги по плану): страница художника и блоки, прайс и калькулятор, заявка, заказы и этапы, загрузка
изображений, админка, вход через VK, письма по заказам.

## Отличия от ТЗ
- Нет ORM: запросы пишутся на SQL через `pg`. Для каркаса этого достаточно, Drizzle можно добавить, когда таблиц в работе станет много.
- Возраст не хранится флагом `is_minor`, а считается из даты рождения (`user_is_minor()` в базе и `ageStatus()` в коде).
  Так подросток автоматически становится взрослым в день рождения, и флаг не может устареть.
- Адрес страницы художника в 0.1 будет `/@ник`; в каркасе страницы ещё нет, адрес в профиле помечен «появится позже».

## Локальная разработка
Нужны Node 22 и PostgreSQL 16.

```bash
cd platform
npm install
cp .env.example .env          # заполните DATABASE_URL (и SESSION_SECRET, если хотите проверять как в продакшене)
npm run db:migrate            # применить миграции
npm run dev                   # http://localhost:3000
```

Без `SMTP_HOST` код входа печатается в консоль, где запущен `npm run dev`.

Проверки:

```bash
npm run typecheck             # типы
npm test                      # логика: возраст, коды, токены, проверка ввода
npm run db:test               # правила базы на временном Postgres (нужны бинарники PostgreSQL)
```

## Выкладка на сервер (запускаете вы)
Нужен сервер с Docker и Docker Compose, домен с записью A на адрес сервера и открытые порты 80 и 443.
Доступы к серверу никому не передавайте, все команды выполняются у вас.

```bash
git clone <адрес репозитория> && cd <репозиторий>/platform
cp .env.example .env
nano .env                     # SITE_URL, DOMAIN, POSTGRES_PASSWORD, SESSION_SECRET, SMTP_*, MAIL_FROM
./deploy/deploy.sh            # сборка, миграции, запуск, ожидание готовности
```

`SESSION_SECRET` сгенерируйте командой `openssl rand -hex 32`. `SITE_URL` пишите с `https://`.
Обновление: `git pull && ./deploy/deploy.sh`. Миграции применяются сами.

Что запускается: `db` (PostgreSQL, наружу не открыт), `migrate` (разово), `app` (наружу не открыт), `caddy` (80 и 443).
Заголовок HSTS в `deploy/Caddyfile` сначала короткий (5 минут). Когда убедитесь, что сайт открывается по HTTPS, увеличьте до года.

Не проверено: образы Docker собирались только как конфигурация (`docker compose config`), потому что на машине разработки
нет запущенного Docker. Сервер запускался так же, как в контейнере (`standalone` вместе со `static` и `public`), и отвечал
правильно. Первый запуск на вашем сервере может вскрыть мелочи, пришлите вывод `docker compose logs`.

## Резервные копии
```bash
./deploy/backup.sh                      # дамп в backups/, хранится 7 последних
./deploy/restore.sh backups/ФАЙЛ.sql.gz # восстановление (спросит подтверждение)
```
Для ночного запуска добавьте в `crontab -e`:
`15 3 * * * cd /путь/к/platform && ./deploy/backup.sh >> backups/backup.log 2>&1`
Копии на том же сервере не защищают от потери сервера: раз в неделю скачивайте свежий дамп к себе
(позже переедем на облачное хранилище в РФ).

## Структура
```
platform/
  src/app/            страницы и серверные действия (вход, регистрация, профиль, служебные)
  src/components/     формы входа и регистрации, переключатель темы
  src/lib/            возраст, коды, токены, проверка ввода, база, почта, сессии, лимиты, тексты (ru.ts)
  db/migrations/      SQL-миграции (0001 — полная схема)
  db/migrate.mjs      применение миграций
  db/tests/           проверка правил базы
  tests/              тесты логики
  deploy/             Caddyfile, deploy.sh, backup.sh, restore.sh
  Dockerfile, docker-compose.yml
```
