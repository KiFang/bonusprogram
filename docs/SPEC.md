# Артоки — спецификация

Бонусная программа для художников в виде Telegram Mini App и бота.
Клиент заказывает арт и получает АРТы, художник начисляет их по уровню клиента.

- Валюта: **АРТ**. 1 АРТ = 1 ₽ = 0,5 ★ (Telegram Stars).
- Интерфейс: Telegram Mini App и бот. Тёмная тема, шрифты Unbounded / Golos Text / JetBrains Mono.
- Макет: https://claude.ai/artifact/L4bTCfQ75WJriMWhCKQgLN
- Рабочий пробник: https://claude.ai/artifact/Av2BkwFHdTZ5cRzpSriuVz

## 1. Роли

| Роль | Что делает |
|---|---|
| Участник | Вступает в программы, копит и тратит АРТы, видит уровни, заказы и коллекцию артов |
| Художник | Начисляет и списывает АРТы, настраивает уровни, ведёт заказы и слоты |
| Админ группы | Управляет составом группы и общими настройками |
| Админ платформы | Приглашает художников, рассматривает заявки на вступление |

## 2. Программы и кошельки

- **Программа** — либо **группа** художников с общим кошельком, либо **соло**-художник с личным кошельком.
- Группа работает как друзья с общими очками. **Взаимных расчётов между художниками нет.**
- Баланс участника хранится отдельно в каждой программе.
- **Уровень считается у каждого художника отдельно**, по сумме денег, которые клиент заплатил именно ему. Это верно и внутри группы.

### Приём «чужих» АРТов в группе
АРТы в общем кошельке помнят, у какого художника они заработаны. Художник выбирает один из режимов:
- `unlimited`: принимает любые АРТы группы без ограничений (по умолчанию);
- `by_tier`: чужие АРТы принимаются в пределах `foreign_pct` от суммы заказа. Этот процент задаётся на каждом уровне, свои АРТы идут по обычному `pay_pct`.

При списании сначала расходуются АРТы с ближайшим сгоранием (бонусные), затем свои АРТы этого художника, затем чужие.

## 3. Уровни (настраивает художник, обычно 3)

| Поле | Пример |
|---|---|
| name | Эскиз / Холст / Шедевр |
| min_spent | 0 / 10 000 / 30 000 ₽ |
| earn_pct — сколько % оплаты возвращается АРТами | 3 / 5 / 8 |
| pay_pct — какую долю заказа можно оплатить АРТами | 20 / 30 / 50 |
| foreign_pct — лимит чужих АРТов (режим `by_tier`) | 5 / 10 / 20 |
| perks | «Приоритет в очереди · бесплатная правка» |
| early_access_hours — ранний доступ к слотам | 0 / 12 / 24 |

- Первый уровень всегда начинается с 0.
- При изменении уровней прошлые операции не пересчитываются: в журнале хранится снимок уровня на момент операции.
- При оплате частично АРТами начисление идёт только на часть, оплаченную деньгами.

## 4. Вступление

- **Ссылка в один тап:** `t.me/<bot>?startapp=j_<slug>`, где slug — ник художника или название группы. Ссылка открывает Mini App сразу с экраном вступления.
- Команда: `/bonusp <группа или ник>` (запасной вариант).
- Каждому участнику выдаётся постоянный код `KF-XXXX` и QR-код, их показывают художнику на кассе.

## 5. Начисление

1. **Касса в Mini App:** код или QR → сумма → расчёт → подтверждение.
2. **Прямо в переписке с клиентом.** Бот не видит личных чатов, поэтому есть два способа:
   - **Inline-режим (работает у всех):** художник пишет в чате с клиентом `@artoki_bot 3000`. Бот предлагает карточку «Начислить за заказ 3 000 ₽», и та уходит в чат с кнопкой «Забрать АРТы». Бот узнаёт клиента по нажатию кнопки и считает АРТы по его уровню у этого художника. Кнопку нельзя нажать самому художнику, она одноразовая и действует 48 часов. Нажатие заодно служит подтверждением со стороны клиента.
   - **Telegram Business (для художников с Premium):** художник подключает бота к своему бизнес-аккаунту. Тогда в переписке с клиентом буквально работает `/addart 3000`: бот знает собеседника, начисляет АРТы и отвечает в том же чате.
3. Отмена операции художником возможна в течение 24 часов. Отмена оформляется записью `reversal`, операции не удаляются.

## 6. Бонусы и акции

- **Приведи друга:** ссылка `?start=ref_<code>`. Оба получают АРТы после первого оплаченного заказа друга. Минимальная сумма заказа и размер бонуса задаются настройками.
- **День рождения:** художник или группа выбирает один из вариантов:
  - временные бонусные АРТы со сгоранием через N дней;
  - повышенный процент начисления у всех художников группы в течение N дней вокруг даты рождения.
- **Акции художника:** множитель начисления на период (например, x2 на выходных).
- **Подарочные сертификаты** двух видов: **группы** (тратится у любого художника группы) и **художника**. Покупаются напрямую у художника (он отмечает оплату) или через бота за Stars. Сертификат активируется по ссылке `?startapp=gift_<code>`.

## 7. Заказы и слоты

- **Статус заказа:** очередь → скетч → покраска → готово. Этапы художник настраивает сам. На каждой смене статуса клиент получает уведомление в боте. Оплаты (в том числе предоплата частями) привязываются к заказу, и на каждую начисляются АРТы.
- **Слоты:** у художника три режима: `open` (N слотов, ранний доступ по уровням), `rest` (не принимает заказы) и `unlimited` (без лимита).
- **Моя коллекция:** когда заказ готов, художник прикладывает превью. У клиента собирается галерея с разделением по художникам. Любое изображение можно скрыть, а NSFW помечается.

## 8. Донаты

- **Этап 1:** у каждого художника в профиле есть кнопки его собственных способов доната (Boosty, DonationAlerts, перевод по СБП). Деньги идут напрямую художнику, без комиссии платформы. Художник может отметить донат, и тогда начисляются АРТы (по желанию, по своей ставке).
- **Этап 2:** донат звёздами через бота (`sendInvoice`, валюта XTR). Stars приходят на бот, поэтому нужен учёт и периодическая выплата художникам. Это отдельная юридическая и учётная задача, её делаем только после этапа 1.
- **Общий сбор группы:** цель с прогресс-баром (например, стенд на фестивале или артбук).

## 9. Заявки художников

Художник заполняет в Mini App форму: ник, портфолио, соцсети, в какую группу хочет или соло. Админ получает заявку в бот и одобряет или отклоняет её одной кнопкой. Пока система сырая, работает только вход по приглашению.

## 10. Стек

- **Supabase:** Postgres с RLS, Storage (превью артов), Edge Functions на Deno для webhook бота (grammY) и серверной логики.
- **Mini App:** React + Vite + TypeScript + `@telegram-apps/sdk`, хостинг на Netlify.
- **Авторизация:** Edge Function проверяет Telegram `initData` (HMAC) и выдаёт JWT для RLS.
- **Деньги:** всё, что меняет баланс, делается только через SQL-функции (`security definer`) с проверкой прав и расчётом на сервере.

## 12. Этапы

1. **MVP:** программы и кошельки, уровни, касса, inline-начисление, бот (`/start`, `/bonusp`, `/balance`), вход по ссылке, отмена операций, режим приёма чужих АРТов.
2. **v1:** заказы и статусы, слоты, коллекция артов, «Приведи друга», день рождения, донат-ссылки.
3. **v2:** сертификаты, акции, `/addart` через Telegram Business, заявки художников, оплата и донаты через Stars, общий сбор группы.

## 13. Решения по деталям

- **Сертификаты.** Сертификат художника зачисляется как АРТы этого художника (`origin_artist_id` = художник). Если художник состоит в группе, то у коллег с режимом `by_tier` такие АРТы считаются чужими, и их лимит действует. Сертификат группы зачисляется без художника-источника и не считается чужим ни для кого.
- **Донаты.** АРТы за донаты начисляются, только если художник это включил.
- **Сгорание.** АРТы не сгорают. Художник может задать срок жизни (`points_ttl_days`) для АРТов, заработанных у него.

## 14. Решения по V1

- **Приведи друга.** Включает и настраивает группа (админ группы) или соло-художник: размер бонуса другу и пригласившему, минимальная сумма первого заказа. АРТы зачисляются в кошелёк программы, где друг сделал заказ.
- **Заказ** заводится только на участника программы (клиент сначала вступает по ссылке или коду).
- **Этапы заказа.** У художника есть шаблон (по умолчанию «Очередь → Скетч → Покраска → Готово»), в конкретном заказе этапы можно поправить.
- **Коллекция артов** видна только самому клиенту; публичный режим позже.
